- `hypequery init --framework django|flask` scaffolds for Django and Flask instead of the standalone app. Django gets an `analytics.py` (registry, tenant function and an example view) for an existing project, and the README shows the `settings.py` and `urls.py` lines. Flask gets an `app.py` using the `Hypequery` extension. Until wired to a login, the Django view requires `@login_required`, the Flask route answers 401 (a `signed_in()` stub returns `False`), and the tenant function returns `None`, so tenant-keyed datasets refuse to run. `pyproject.toml` asks for the `django` or `flask` extra. The standalone app stays the default.
