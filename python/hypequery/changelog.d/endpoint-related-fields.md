- Served dataset and metric endpoints no longer expose related datasets' fields by default. Previously a caller refused by the shipments endpoint could still read `shipment.carrier` through the orders endpoint, and the client contract advertised those fields. Related dimensions, related measures, and named filters defined on a related field now need `include_related={"shipment"}` on `create_dataset_endpoint`, `add_dataset_endpoint` or the metric equivalents. Without it, they are refused with `400 VALIDATION_ERROR` and left out of the endpoint's client contract. So are measures whose fixed filters read a related field, directly or through a derived measure; an omitted `measures` list selects only the base measures the endpoint can serve, and a metric endpoint for such a measure is refused when created. `ClientEndpointDefinition` gains `related` for the same purpose; it defaults to `None`, which exports every relationship as before.
