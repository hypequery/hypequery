- Run datasets on Postgres. `create_postgres_executor` and `create_async_postgres_executor` (extra `hypequery[postgres]`) execute queries the client compiles with the new Postgres dialect; results match ClickHouse for the same rows, including DST buckets, half-to-even `round` and NULL ordering. Queries run read-only with a server-side statement timeout and cancellation, and time-key filters keep an index on the column usable. Pass `search_path=` to pin name resolution with `pg_catalog` first and `pg_temp` last; statements are never prepared by name, so PgBouncer's transaction mode works.
- `TypedParameter.clickhouse_type` is now `sql_type`, `CompiledQuery` records the `dialect` it was compiled for, and executors refuse queries compiled for another dialect. `SafeIdentifier` no longer renders SQL itself; quote names through the dialect.
- Result cache keys fold in the engine for non-ClickHouse executors, exactly as TypeScript does, so a Postgres client and a ClickHouse client sharing a store never serve each other's results. ClickHouse keys are unchanged.
- `hypequery init` and `hypequery generate datasets` support Postgres. Use `--database postgres`, or let the CLI detect it when only a Postgres URL is set. Discovery reads the current schema's catalog in a read-only, time-limited transaction. The scaffolded project runs on `create_postgres_executor` with the `postgres` extra.
