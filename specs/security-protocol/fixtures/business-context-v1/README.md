# Business context v1 fixtures

These fixtures pin the business context document (`kind:
"hypequery-business-context"`, `version: 1`): reviewed guidance for agents
and analysts (summary, KPIs, glossary, conventions, caveats) that travels
beside a deployment contract in a v2 bundle. It never changes query results.

- `success.json` contains accepted documents; `empty` says whether the
  validated document carries no authored content beyond its header.
- `rejections.json` maps invalid documents to a stable error code and the
  JSON path it names. A case may carry `limits` (`maxTextLength`, `maxItems`,
  `maxBytes`) that tighten the v1 ceilings.
- `identity.json` pins canonical bytes and the identity: SHA-256 over
  `hypequery:business-context:v1\0` and the RFC 8785 canonical UTF-8 bytes.

Text is trimmed with ECMAScript's `trim`, and its length counts UTF-16 code
units (4096 at most). Lists hold at most 100 items, and empty lists are dropped
from the canonical form. KPI names and glossary terms must be unique after
NFKC normalization, lower-casing and folding each run of ECMAScript
whitespace to one space. The canonical encoding is at most 1 MiB.

The conformance runner compares rejection codes; the TypeScript
(`packages/protocol`) and Python (`python/hypequery`) test suites also compare
each rejection's `path`. Unsafe host-language objects are covered by each
implementation's own tests, since JSON cannot describe them.

The expected values were generated by running `@hypequery/protocol`; regenerate
them from the reference implementation rather than editing them by hand.
