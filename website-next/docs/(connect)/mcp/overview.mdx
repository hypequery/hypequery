`@hypequery/mcp` exposes your Hypequery semantic layer through the Model Context Protocol. Agents can discover datasets, inspect schema metadata, query named metrics, and run governed dataset queries without receiving raw SQL access.

Use MCP when you want an agent to work inside a constrained analytics vocabulary:

- expose only the datasets you register
- expose only named metrics you attach to those datasets
- let agents inspect dimensions, labels, descriptions, filters, tenant keys, and time keys
- execute through the same `createDatasetClient` path used by the rest of your app
- avoid handing an LLM a direct SQL console

<Callout type="info">
  MCP is a capability boundary, not an authentication layer. If your data is multi-tenant, read <a href="/docs/mcp/safety">Safety model</a> before exposing a server broadly.
</Callout>

## How it fits together

| Piece | What it does |
| --- | --- |
| `hypequery mcp` (CLI) | Starts an MCP server for your project |
| MCP server (`@hypequery/mcp`) | Gives an agent tools to discover datasets and query them |
| Datasets | Define what the agent is allowed to query |

## Quick start with the CLI

If your project already serves datasets with `@hypequery/serve`, the CLI can expose them over MCP with no extra
config. Install the MCP server package alongside the CLI:

<CodeBlock>
```bash
npm install @hypequery/mcp
npm install -D @hypequery/cli
```
</CodeBlock>

Then, from your project root:

<CodeBlock>
```bash
npx hypequery mcp
```
</CodeBlock>

The command finds your Serve API file (`analytics/api.ts`, `hypequery.ts`, or `analytics/queries.ts`, among others)
and serves the datasets registered with `serve({ queryBuilder, datasets })`. Pass a file to choose one explicitly, or
`--path` for a different analytics directory:

<CodeBlock>
```bash
npx hypequery mcp ./src/analytics/api.ts
npx hypequery mcp --path src/analytics
```
</CodeBlock>

If any dataset has a `tenantKey`, pass the trusted tenant the server should run as. The server refuses to start
without one:

<CodeBlock>
```bash
npx hypequery mcp --tenant acme
```
</CodeBlock>

Check the setup without starting the server:

<CodeBlock>
```bash
npx hypequery mcp --self-test
```
</CodeBlock>

The server speaks MCP over stdio, so an MCP client normally launches it. See [Clients](/docs/mcp/clients) for Claude
Desktop and Cursor configuration.

## Standalone server

Use `@hypequery/mcp` directly when you don't have a Serve API, or want a dedicated config file for the agent.

### Install

<CodeBlock>
```bash
npm install @hypequery/mcp @hypequery/datasets @hypequery/clickhouse
# or
pnpm add @hypequery/mcp @hypequery/datasets @hypequery/clickhouse
```
</CodeBlock>

### Config

Create an ESM config file that exports `datasets` and `analytics`.

<CodeBlock>
```javascript
// mcp-config.mjs
import { createQueryBuilder } from '@hypequery/clickhouse';
import { createDatasetClient, publishDatasets } from '@hypequery/datasets';
import { Orders } from './datasets/orders.js';

const db = createQueryBuilder({
  url: process.env.CLICKHOUSE_URL,
  username: process.env.CLICKHOUSE_USER,
  password: process.env.CLICKHOUSE_PASSWORD,
  database: process.env.CLICKHOUSE_DATABASE,
});

export const datasets = publishDatasets()
  .publish(Orders)
  .build();

export const analytics = createDatasetClient({ queryBuilder: db });
```
</CodeBlock>

Run the MCP server with the config file path:

<CodeBlock>
```bash
npx hypequery-mcp --config ./mcp-config.mjs
```
</CodeBlock>
