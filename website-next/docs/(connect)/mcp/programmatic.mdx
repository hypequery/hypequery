import { CodeBlock } from 'fumadocs-ui/components/codeblock';

Use `startStdioMCPServer` when you want to start the MCP server from your own Node process instead of using the CLI.

<CodeBlock>
```typescript
import { startStdioMCPServer } from '@hypequery/mcp';
import { createDatasetClient } from '@hypequery/datasets';
import { createQueryBuilder } from '@hypequery/clickhouse';
import { datasets } from './datasets/index.js';

const db = createQueryBuilder({
  url: process.env.CLICKHOUSE_URL!,
  username: process.env.CLICKHOUSE_USERNAME!,
  password: process.env.CLICKHOUSE_PASSWORD!,
  database: process.env.CLICKHOUSE_DATABASE!,
});

const analytics = createDatasetClient({ queryBuilder: db });

const server = await startStdioMCPServer({
  datasets,
  analytics,
  name: 'analytics-mcp',
  version: '1.0.0',
});

// The server is now running over stdio.
```
</CodeBlock>

`startStdioMCPServer` returns the server instance once it is connected over stdio. The stdio transport is intended for MCP clients that launch and manage the process.

`createMCPServer(config)` and `server.start()` still work but are deprecated aliases for the same thing.

## Custom transports

The tools are independent of stdio. To serve them over another MCP transport, build an executor and a protocol server and connect your own transport:

<CodeBlock>
```typescript
import { createMCPExecutor, createMCPProtocolServer } from '@hypequery/mcp';

const executor = createMCPExecutor({ datasets, analytics, tenantId: trustedTenantId });
const server = createMCPProtocolServer({ executor, name: 'analytics-mcp', version: '1.0.0' });

await server.connect(transport);
```
</CodeBlock>

To bridge a Python HTTP backend instead of local datasets, use `createMCPHttpExecutor({ url, headers })` as the executor; see the package README.

## Tenant-scoped servers

If registered datasets have `tenantKey`, pass a trusted `tenantId` when creating the MCP server.

<CodeBlock>
```typescript
const server = await startStdioMCPServer({
  datasets,
  analytics,
  tenantId: 'tenant_123',
});
```
</CodeBlock>

The server forwards that value as dataset runtime tenant context for `query_dataset` and `query_metric`.

## Stop the server

If your application owns the lifecycle, call `stop()`.

<CodeBlock>
```typescript
await server.stop();
```
</CodeBlock>

## Config shape

The programmatic API accepts the same core inputs as the CLI config, plus optional server metadata and tenant scope.

<CodeBlock>
```typescript
type MCPServerConfig = {
  datasets: Record<string, AnyDatasetInstance | Record<string, unknown>>;
  analytics: DatasetClient;
  name?: string;
  version?: string;
  tenantId?: string;
  includeSql?: boolean;
  // defaultResultSize 100; maxResultSize and maxOffset up to 10,000;
  // maxDimensions/maxMeasures up to 50, maxFilters up to 100, maxOrderBy up to 50
  queryLimits?: MCPQueryLimits;
  // timeoutMs default 30s (max 120s); maxResponseBytes default 1 MiB (max 10 MiB)
  executionBudget?: MCPExecutionBudget;
  // maxTools default 64 (max 256); maxManifestBytes default 256 KiB (max 1 MiB)
  catalogBudget?: MCPCatalogBudget;
};
```
</CodeBlock>

Set `includeSql: true` only in trusted debugging contexts. Query tools redact generated SQL by default.
