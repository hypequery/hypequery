Most projects don't need this: `hypequery mcp` starts the server for you ([Quickstart](/docs/mcp/quickstart)). Use
`createMCPServer` when your own Node process has to start and stop the MCP server, over stdio. To serve over HTTP from
your own process, use `createMCPHttpHandler` instead: see [Remote MCP over HTTP](/docs/mcp/remote#in-your-own-server).

<CodeBlock>
```typescript
import { createMCPServer } from '@hypequery/mcp';
import { createDatasetClient } from '@hypequery/datasets';
import { createQueryBuilder } from '@hypequery/clickhouse';
import { datasets } from './datasets/index.js';

const db = createQueryBuilder({
  url: process.env.CLICKHOUSE_URL!,
  username: process.env.CLICKHOUSE_USERNAME!,
  password: process.env.CLICKHOUSE_PASSWORD!,
  database: process.env.CLICKHOUSE_DATABASE!,
});

const analytics = createDatasetClient({ queryBuilder: db });

const server = await createMCPServer({
  datasets,
  analytics,
  name: 'analytics-mcp',
  version: '1.0.0',
});

// The server is now running over stdio.
```
</CodeBlock>

`createMCPServer` returns the server instance after calling `start()`. The stdio transport is intended for MCP clients that launch and manage the process.

## Tenant-scoped servers

If registered datasets have `tenantKey`, pass a trusted `tenantId` when creating the MCP server.

<CodeBlock>
```typescript
const server = await createMCPServer({
  datasets,
  analytics,
  tenantId: 'tenant_123',
});
```
</CodeBlock>

The server forwards that value as dataset runtime tenant context for `query_dataset` and `query_metric`.

## Stop the server

If your application owns the lifecycle, call `stop()`.

<CodeBlock>
```typescript
await server.stop();
```
</CodeBlock>

## Config shape

The programmatic API accepts the same core inputs as the CLI config, plus optional server metadata and tenant scope.

<CodeBlock>
```typescript
type MCPServerConfig = {
  datasets: Record<string, Record<string, unknown>>;
  analytics: DatasetClient;
  name?: string;
  version?: string;
  tenantId?: string;
  includeSql?: boolean;
};
```
</CodeBlock>

Set `includeSql: true` only in trusted debugging contexts. Query tools redact generated SQL by default.
