MCP should expose a governed analytics layer, not a database console.

With hypequery MCP, the agent can only use the datasets you register. It receives tools for discovery and semantic querying. It does not receive a raw SQL execution tool.

## What MCP constrains

- which datasets are visible
- which dimensions and measures can be requested
- which filter operators the tool schema accepts
- query execution through the dataset client
- tenant scoping when the server is configured with a trusted `tenantId`

MCP can also expose relationship metadata through schema introspection, but current dataset execution is still same-dataset.

## What MCP does not replace

MCP does not replace authentication, authorization, or tenant identity. The stock stdio server receives tool calls from a local MCP client and executes them through the `analytics` dataset client you provide.

<Callout type="warn">
  A stdio server, or an HTTP server behind one shared key, runs as one caller with one tenant. Do not share one between
  tenants. To serve several users or tenants from one server, use [remote MCP](/docs/mcp/remote) with your app's auth
  or OAuth, so each caller's tenant comes from their own verified credential.
</Callout>

## Safer patterns

Prefer one of these patterns:

- run MCP for local development or internal admin use only
- expose only non-sensitive aggregate datasets
- run a tenant-specific MCP process with `tenantId`
- keep sensitive tables out of the exported `datasets` registry
- enable `includeSql` only in trusted debugging sessions

## Registry boundary

The exported `datasets` registry is the main boundary.

<CodeBlock>
```javascript
import { publishDatasets } from '@hypequery/datasets';

export const datasets = publishDatasets()
  .publish(Orders)
  .build();
```
</CodeBlock>

If a dataset is not in this object, the MCP server cannot list it, introspect it, or query it.

## Tenant boundary

If registered datasets have `tenantKey`, the MCP server requires a trusted tenant scope. In the programmatic API, pass `tenantId`.

<CodeBlock>
```typescript
await createMCPServer({
  datasets,
  analytics,
  tenantId: 'tenant_123',
});
```
</CodeBlock>

The server forwards that value into dataset execution as runtime tenant context. Agents should not choose tenant ids through filters.

With the CLI, pass the tenant as `npx hypequery mcp --tenant <id>`. It refuses to start for tenant-scoped datasets without one.

The config-file server (`npx @hypequery/mcp --config`) does not accept a tenant, so it cannot serve tenant-keyed datasets: startup fails with `MCP server tenantId is required for tenant-scoped datasets`. Use `hypequery mcp --tenant` or the programmatic `createMCPServer({ ..., tenantId })` instead.

Either way, a stdio server process serves one tenant. Over HTTP with your app's auth or OAuth, each session gets the
tenant from its caller's verified credential instead; see [Remote servers](#remote-servers).

## Remote servers

`hypequery mcp --http` puts the server on a network, so who can reach it matters as much as what it exposes.

- **Credentials.** Every request needs one. A shared key (`HYPEQUERY_MCP_KEY`) is one caller: everyone holding it sees
  the same data. Your app's auth or OAuth gives each caller their own identity and tenant.
- **Tenant.** Over HTTP the tenant comes from the verified credential, never from a tool argument or the prompt. A
  session belongs to the caller that opened it; anyone else using its id gets `404`.
- **Per-dataset rules (TypeScript).** MCP applies `defineServe`'s global `auth` and `tenant` only. Per-endpoint `auth`,
  roles, scopes and middlewares, and global middlewares, are not applied, so `hypequery mcp --http` refuses to verify
  callers with your app's auth when any are set. In Python, every call goes through the API's own policy.
- **Network.** Requests must name an allowed `Host`, which stops DNS-rebinding attacks, and browser pages must come from
  `--allowed-origins`. Terminate TLS in front of the server; it speaks plain HTTP.
- **OAuth tokens.** The JWT audience must be exactly the server's resource URL, so a token issued for another API can't
  open a session. The CLI refuses to start otherwise.

[Remote MCP over HTTP](/docs/mcp/remote) has the full order of checks and deployment notes.

## Raw SQL boundary

The MCP server exposes semantic tools:

- `list_datasets`
- `get_dataset_schema`
- `query_dataset`
- `query_metric`

It does not expose a generic `run_sql` tool.

Generated SQL and SQL-backed field expressions are also redacted from MCP responses by default. Programmatic servers can opt in with `includeSql: true` for trusted local debugging.

For the broader application boundary between semantic runtime input and trusted raw SQL APIs, see [Trust Boundaries](/docs/reference/trust-boundaries).
