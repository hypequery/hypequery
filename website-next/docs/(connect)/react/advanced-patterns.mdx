Learn advanced techniques for configuring and optimizing your React hooks with hypequery.

## HTTP Method Configuration

Routes from a manifest use the server's method, so dataset and metric endpoints, including every route in a client generated from a Python contract, use `POST`. For routes the manifest does not cover, `useQuery` issues `GET` and `useMutation` issues `POST`. Override the method per query with `config`, which is applied on top of the manifest:

<CodeBlock>
<Pre>
```ts
import { createHooks } from '@hypequery/react';
import type { InferApiType } from '@hypequery/serve';
import type { api } from '@/analytics/queries';
import manifest from '@/analytics/hypequery-manifest.json';

type Api = InferApiType<typeof api>;

export const { useQuery, useMutation } = createHooks<Api>({
  baseUrl: '/api/analytics',
  manifest,
  config: {
    weeklyRevenue: { method: 'GET' },    // Read-only queries
    tripStats: { method: 'GET' },
    rebuildMetrics: { method: 'POST' },  // Write operations
    updateMetric: { method: 'PUT' },
  },
});
```
</Pre>
</CodeBlock>

### When to Use Different Methods

- **GET**: Read-only queries, safe to cache
- **POST**: Write operations, mutations, or queries with large inputs
- **PUT**: Updates to specific resources
- **DELETE**: Removal operations

## Auto-Config from Server

Instead of maintaining routes by hand, let the server tell the client each endpoint's method and path.

### Option A: Static Manifest (Next.js / Remix / any bundler)

Generate the route manifest as JSON at build time and import it:

<CodeBlock>
<Pre>
```bash
npx hypequery generate:manifest analytics/api.ts --output analytics/hypequery-manifest.json
```
</Pre>
</CodeBlock>

<CodeBlock>
<Pre>
```ts
// lib/analytics.ts
import { createHooks } from '@hypequery/react';
import type { InferApiType } from '@hypequery/serve';
import type { api } from '@/analytics/api';
import manifest from '@/analytics/hypequery-manifest.json';

type Api = InferApiType<typeof api>;

export const { useQuery, useMutation } = createHooks<Api>({
  baseUrl: '/api/analytics',
  manifest, // ✅ Methods and paths, no server code in the bundle
});
```
</Pre>
</CodeBlock>

The manifest carries the method and full path for every query, metric, and dataset key, so client and
server stay in sync without the client importing anything from the server.

<Callout type="warn" title="Passing `api` directly does not work in a client module">
  An earlier version of this page suggested `createHooks({ api })` with a value import of `api`.
  That only holds if the module is server-only. `lib/analytics.ts` is imported by client components,
  so a value import of `api` bundles `initServe` and `@hypequery/clickhouse` for the browser — and
  in Next.js App Router it fails the build with `Can't resolve 'fs/promises'`.

  Use the static manifest above, or the config endpoint in Option B. Reserve `api` and
  `api.manifest()` for server-side code.
</Callout>

<Callout type="info">
  A `manifest` (or an explicit `config` entry with a `path`) is **required**. Serve mounts named
  queries at `<basePath>/queries/<name>` and datasets at `<basePath>/datasets/<name>/query`, so no
  route matches its map key. The manifest in Option B includes every route too.
</Callout>

### Option B: Manifest Endpoint (SPAs / Vite)

If you'd rather not run a build step, serve the manifest from the server and fetch it at runtime:

**1. Create a manifest endpoint:**
<CodeBlock>
<Pre>
```ts
// app/api/hypequery-manifest/route.ts
import { api } from '@/analytics/queries';

export function GET() {
  return Response.json(api.manifest());
}
```
</Pre>
</CodeBlock>

This runs on the server, so the value import of `api` is safe here.

**2. Create hooks without a config.** They read their client from `HypequeryProvider`:
<CodeBlock>
<Pre>
```ts
// lib/analytics.ts
import { createHooks } from '@hypequery/react';
import type { InferApiType } from '@hypequery/serve';
import type { api } from '@/analytics/queries';

export type Api = InferApiType<typeof api>;

export const { useQuery, useMutation } = createHooks<Api>();
```
</Pre>
</CodeBlock>

**3. Build the client once the manifest loads:**
<CodeBlock>
<Pre>
```tsx
// app/providers.tsx
'use client';

import { useEffect, useState, type ReactNode } from 'react';
import { createHypequeryClient, HypequeryProvider, type HypequeryClient } from '@hypequery/react';
import type { Api } from '@/lib/analytics';

export function AppProviders({ children }: { children: ReactNode }) {
  const [client, setClient] = useState<HypequeryClient<Api> | null>(null);

  useEffect(() => {
    fetch('/api/hypequery-manifest')
      .then((res) => res.json())
      .then((manifest) => setClient(createHypequeryClient<Api>({ baseUrl: '/api/analytics', manifest })));
  }, []);

  if (!client) return <div>Loading...</div>;

  // HypequeryProvider also provides a TanStack QueryClient; pass `queryClient` to reuse your own.
  return <HypequeryProvider client={client}>{children}</HypequeryProvider>;
}
```
</Pre>
</CodeBlock>

## Query Client Access

Access the TanStack Query client directly for advanced cache management:

<CodeBlock>
<Pre>
```tsx
import { useQueryClient } from '@tanstack/react-query';

function MetricsPanel() {
  const queryClient = useQueryClient();
  const { data } = useQuery('metrics', {});

  const handleRefresh = () => {
    // Invalidate every cached `metrics` query (see Query Keys below)
    queryClient.invalidateQueries({ queryKey: ['hypequery', 'analytics', 'metrics'] });

    // Or clear entire cache
    queryClient.clear();
  };

  return (
    <div>
      <div>{data?.total}</div>
      <button onClick={handleRefresh}>Refresh</button>
    </div>
  );
}
```
</Pre>
</CodeBlock>

## Cache Invalidation

### Invalidate After Mutations

Automatically refresh related queries when data changes:

<CodeBlock>
<Pre>
```tsx
import { useMutation, useQuery } from '@/lib/analytics';
import { useQueryClient } from '@tanstack/react-query';

function MetricsManager() {
  const queryClient = useQueryClient();
  const { data: metrics } = useQuery('metrics', {});

  const rebuild = useMutation('rebuildMetrics', {
    onSuccess: () => {
      // Invalidate related queries (keys use the client's cacheKey; see Query Keys below)
      queryClient.invalidateQueries({ queryKey: ['hypequery', 'analytics', 'metrics'] });
      queryClient.invalidateQueries({ queryKey: ['hypequery', 'analytics', 'weeklyRevenue'] });
    },
  });

  return (
    <button onClick={() => rebuild.mutate({ force: true })}>
      Rebuild
    </button>
  );
}
```
</Pre>
</CodeBlock>

### Prefetching

Preload data before it's needed:

<CodeBlock>
<Pre>
```tsx
import { useQueryClient } from '@tanstack/react-query';

function Dashboard() {
  const queryClient = useQueryClient();

  useEffect(() => {
    // Prefetch on mount, under the same key `useQuery('weeklyRevenue', input)` reads
    queryClient.prefetchQuery({
      queryKey: ['hypequery', 'analytics', 'weeklyRevenue', { startDate: '2025-01-01' }],
      queryFn: () => fetch('/api/analytics/queries/weeklyRevenue?startDate=2025-01-01')
        .then(res => res.json()),
    });
  }, []);

  // ...
}
```
</Pre>
</CodeBlock>

## Query Keys

hypequery hooks use a fixed query-key structure: `['hypequery', cacheKey, name]`, or `['hypequery', cacheKey, name, input]` when the query has input. `cacheKey` is the client's cache scope: the `cacheKey` option you passed to `createHooks`, `createAnalyticsHooks` or `createHypequeryClient`, or a generated one per client otherwise. Dataset hooks key on their resolved name (`dataset:<name>`). Use these keys with TanStack's cache APIs:

<CodeBlock>
<Pre>
```tsx
// Give the client a known scope when you create it...
export const { useQuery } = createHooks<Api>({ baseUrl: '/api/analytics', manifest, cacheKey: 'analytics' });

// ...then invalidate one query (TanStack matches by prefix, so this covers every input).
queryClient.invalidateQueries({ queryKey: ['hypequery', 'analytics', 'weeklyRevenue'] });

// Invalidate every hypequery cache entry, for every client.
queryClient.invalidateQueries({ queryKey: ['hypequery'] });
```
</Pre>
</CodeBlock>

Under a `HypequeryProvider`, read the scope with `useHypequeryClient().cacheKey`.

The key structure is not configurable — relying on the stable `'hypequery'` prefix lets you target hypequery caches without colliding with other TanStack queries.

## Auth headers and token refresh

Add auth tokens with the `headers` option. It accepts a static object or a (optionally async) function that runs per request, so it can supply a fresh short-lived token. Pair it with `onUnauthorized` to refresh credentials and retry once on a `401`:

<CodeBlock>
<Pre>
```tsx
export const { useQuery, useMutation } = createHooks<Api>({
  baseUrl: '/api/analytics',
  manifest,
  headers: async () => ({
    Authorization: `Bearer ${await getAuthToken()}`,
  }),
  onUnauthorized: async () => {
    // Runs on a 401; refresh the token, then the request retries once.
    await refreshSession();
  },
});
```
</Pre>
</CodeBlock>

If you need full control over the request, override the fetch implementation with `fetchFn`:

<CodeBlock>
<Pre>
```tsx
export const { useQuery, useMutation } = createHooks<Api>({
  baseUrl: '/api/analytics',
  manifest,
  fetchFn: async (url, options) => {
    const token = getAuthToken();

    return fetch(url, {
      ...options,
      headers: {
        ...options?.headers,
        Authorization: `Bearer ${token}`,
      },
    });
  },
});
```
</Pre>
</CodeBlock>

## Suspense Mode

<Callout type="info">
  TanStack Query v5 removed the per-call `suspense: true` flag in favor of dedicated `useSuspenseQuery`/`useSuspenseInfiniteQuery` hooks. hypequery's hooks wrap the non-suspense hooks, so handle loading with `isLoading` (shown elsewhere on this page). If you need Suspense, read the endpoint with your own `useSuspenseQuery` call against the same route.
</Callout>

Use React Suspense for declarative loading states:

<CodeBlock>
<Pre>
```tsx
import { Suspense } from 'react';
import { useSuspenseQuery } from '@tanstack/react-query';

function MetricsChart() {
  // Throws a promise while loading, so the parent <Suspense> shows its fallback.
  const { data } = useSuspenseQuery({
    queryKey: ['hypequery', 'analytics', 'weeklyRevenue', { startDate: '2025-01-01' }],
    queryFn: () =>
      fetch('/api/analytics/queries/weeklyRevenue?startDate=2025-01-01').then((res) => res.json()),
  });

  return <div>Total: ${data.total}</div>;
}

function Dashboard() {
  return (
    <Suspense fallback={<div>Loading metrics...</div>}>
      <MetricsChart />
    </Suspense>
  );
}
```
</Pre>
</CodeBlock>

## Error Boundaries

Handle errors declaratively with error boundaries:

<CodeBlock>
<Pre>
```tsx
import { ErrorBoundary } from 'react-error-boundary';

function Dashboard() {
  return (
    <ErrorBoundary
      fallback={<div>Failed to load metrics</div>}

      <MetricsPanel />
    </ErrorBoundary>

}
```
</Pre>
</CodeBlock>

## Advanced TanStack Query Options

All TanStack Query options are supported:

<CodeBlock>
<Pre>
```tsx
const { data, refetch, isFetching } = useQuery(
  'weeklyRevenue',
  { startDate: '2025-01-01' },
  {
    // Caching
    staleTime: 5 * 60 * 1000, // 5 minutes
    gcTime: 10 * 60 * 1000, // 10 minutes (was `cacheTime` before TanStack v5)

    // Refetching
    refetchOnMount: true,
    refetchOnWindowFocus: false,
    refetchInterval: 30000, // Poll every 30s

    // Conditional fetching
    enabled: isAuthenticated,

    // Retries
    retry: 3,
    retryDelay: (attemptIndex) => Math.min(1000 * 2 ** attemptIndex, 30000),
  }
);
```
</Pre>
</CodeBlock>

<Callout type="info">
  Per-query `onSuccess`/`onError` callbacks were removed from `useQuery` in TanStack Query v5. Use `useMutation` callbacks for writes, or subscribe via the global `QueryCache` if you need query-level side effects.
</Callout>

## Background Refetching

Keep data fresh with background updates:

<CodeBlock>
<Pre>
```tsx
function LiveMetrics() {
  const { data, dataUpdatedAt } = useQuery(
    'liveMetrics',
    {},
    {
      staleTime: 0, // Always consider stale
      refetchInterval: 5000, // Refetch every 5 seconds
      refetchIntervalInBackground: true, // Continue even when tab is hidden
    }
  );

  return (
    <div>
      <div>Active Users: {data?.activeUsers}</div>
      <div className="text-xs text-gray-500">
        Updated: {new Date(dataUpdatedAt).toLocaleTimeString()}
      </div>
    </div>
  );
}
```
</Pre>
</CodeBlock>

## Parallel Queries

Execute multiple queries efficiently:

<CodeBlock>
<Pre>
```tsx
function Dashboard() {
  const revenue = useQuery('weeklyRevenue', { startDate: '2025-01-01' });
  const users = useQuery('activeUsers', { limit: 100 });
  const metrics = useQuery('systemMetrics', {});

  // All three queries run in parallel
  if (revenue.isLoading || users.isLoading || metrics.isLoading) {
    return <div>Loading...</div>;
  }

  return (
    <div>
      <RevenueChart data={revenue.data} />
      <UserList data={users.data} />
      <MetricsPanel data={metrics.data} />
    </div>
  );
}
```
</Pre>
</CodeBlock>

## Infinite Queries

hypequery hooks include offset-paginated `useInfiniteQuery`, `useInfiniteDataset` and `useInfiniteMetric`. You don't wire up `getNextPageParam` yourself — the hooks advance pages using the `meta.pagination` the server returns (requested automatically via the `x-include-meta` header). Set `limit` as the page size; `offset`, if provided, is the starting offset.

<CodeBlock>
<Pre>
```tsx
import { useInfiniteDataset } from '@/lib/analytics';

function InfiniteOrders() {
  const {
    data,
    fetchNextPage,
    hasNextPage,
    isFetchingNextPage,
  } = useInfiniteDataset('orders', {
    dimensions: ['country', 'status'],
    measures: ['revenue'],
    limit: 20, // page size
  });

  return (
    <div>
      {data?.pages.map((page, i) => (
        <div key={i}>
          {/* Each page is the endpoint response: `{ data, meta }`. */}
          {page.data.map((row, j) => (
            <div key={j}>{row.country}: {row.revenue}</div>
          ))}
        </div>
      ))}
      {hasNextPage && (
        <button onClick={() => fetchNextPage()} disabled={isFetchingNextPage}>
          {isFetchingNextPage ? 'Loading...' : 'Load More'}
        </button>
      )}
    </div>
  );
}
```
</Pre>
</CodeBlock>

`useInfiniteMetric` takes a metric name and the same input as `useMetric`. `useInfiniteQuery` works the same way for a plain query whose endpoint returns `meta.pagination`.
