Hypequery MCP runs over stdio, so your MCP client launches the server. There are two ways to launch it:

- **`hypequery mcp`** serves the datasets in your Serve API file. Pass the file's absolute path and it works from
  whatever directory the client launches it in.
- **`@hypequery/mcp --config`** runs the [standalone server](/docs/mcp/overview#standalone-server) with a dedicated
  config file.

## Claude Desktop with `hypequery mcp`

Add a server entry to Claude Desktop's config file:

- macOS: `~/Library/Application Support/Claude/claude_desktop_config.json`
- Windows: `%APPDATA%\Claude\claude_desktop_config.json`

<CodeBlock>
```json
{
  "mcpServers": {
    "hypequery": {
      "command": "npx",
      "args": ["-y", "@hypequery/cli", "mcp", "/absolute/path/to/analytics/api.ts"],
      "env": {
        "CLICKHOUSE_URL": "https://example.clickhouse.cloud:8443",
        "CLICKHOUSE_USER": "default",
        "CLICKHOUSE_PASSWORD": "password",
        "CLICKHOUSE_DATABASE": "analytics"
      }
    }
  }
}
```
</CodeBlock>

The API file's imports, including `@hypequery/mcp`, resolve from its project, so install them there as usual. Your
project's `.env` is not loaded when the client launches from another directory, so pass connection settings in `env`.
Add `"--tenant", "<id>"` to `args` if any dataset is tenant-scoped. Cursor accepts the same `command`, `args`, and
`env` in its MCP configuration.

Restart Claude Desktop after changing the config.

## Standalone server

### Claude Desktop

To run the standalone server instead, point the client at your config file:

<CodeBlock>
```json
{
  "mcpServers": {
    "hypequery": {
      "command": "npx",
      "args": [
        "-y",
        "@hypequery/mcp",
        "--config",
        "/absolute/path/to/mcp-config.mjs"
      ],
      "env": {
        "CLICKHOUSE_URL": "https://example.clickhouse.cloud:8443",
        "CLICKHOUSE_USER": "default",
        "CLICKHOUSE_PASSWORD": "password",
        "CLICKHOUSE_DATABASE": "analytics"
      }
    }
  }
}
```
</CodeBlock>

Restart Claude Desktop after changing the config.

### Cursor

Use the same command and arguments in Cursor's MCP configuration:

<CodeBlock>
```json
{
  "mcpServers": {
    "hypequery": {
      "command": "npx",
      "args": [
        "-y",
        "@hypequery/mcp",
        "--config",
        "/absolute/path/to/mcp-config.mjs"
      ],
      "env": {
        "CLICKHOUSE_URL": "https://example.clickhouse.cloud:8443",
        "CLICKHOUSE_USER": "default",
        "CLICKHOUSE_PASSWORD": "password",
        "CLICKHOUSE_DATABASE": "analytics"
      }
    }
  }
}
```
</CodeBlock>

## Test the server directly

Before connecting a client, check a `hypequery mcp` setup with the same path you put in the client config. It loads
the API file and reports the datasets it would serve, without starting the server:

<CodeBlock>
```bash
npx -y @hypequery/cli mcp /absolute/path/to/analytics/api.ts --self-test
```
</CodeBlock>

For the standalone server, run it from a terminal:

<CodeBlock>
```bash
npx -y @hypequery/mcp --config /absolute/path/to/mcp-config.mjs
```
</CodeBlock>

You should see startup logs on stderr. The process keeps running because the MCP client normally owns its lifecycle.

<Callout type="info">
  Use absolute paths in client config. Desktop clients often launch from a different working directory than your terminal.
</Callout>
