## How the commands behave

- **Credentials.** The same as every Cloud command: `HYPEQUERY_API_TOKEN`, then the management token from
  `hypequery login` or `hypequery login --device`, then the browser sign-in. See [CLI commands](/docs/cloud/cli).
- **Project.** `--project <slug>` names the project. Project operations default to the project your sign-in names.
- **Output.** Each command prints the operation's output as JSON on stdout. With `--json` stdout carries exactly
  that document, or the error envelope (`code`, `message`, `hint`, `docsUrl`, `requestId`, `issues`).
- **Exit codes.** 0 ok, 1 correctable, 2 auth, 3 plan, 4 transient, 5 internal.
- **Destructive operations** need `--yes`. At a terminal the CLI asks instead; without one (or with `--json`,
  `--no-input` or `CI`) it refuses with `CONFIRMATION_REQUIRED` and changes nothing.
- **Secrets.** Secret inputs (a ClickHouse password, an OIDC client secret) come from stdin with
  `--<field>-stdin`, a hidden prompt, or `--input-json`, never a flag value. New keys are printed to stdout once,
  with a warning on stderr.
- **Values.** Lists repeat the flag (`--scopes a --scopes b`); `null` sends JSON null where a field allows it;
  object fields take JSON. `--input-json` takes the whole input as an object, inline, from `@file` or from `-` (stdin).

## feedback

### `hypequery feedback create`

Report a problem with hypequery to its team: a tool that failed in a way its hint didn't fix, a confusing description or error, something missing, or a wrong result. Never include secrets, credentials or customer data; they are stripped anyway. A report never changes data, and the team reads every one.

| Argument or flag | Value | Description |
| --- | --- | --- |
| `--kind` | `bug`, `confusing`, `missing`, `wrong_result`, `other` | bug: something failed; confusing: a description, hint or error misled you; missing: a capability you needed; wrong_result: an answer looked wrong; other. Required. |
| `--summary` | text | One sentence: what went wrong. Required. |
| `--details` | text | What happened, including the error message or code you saw. |
| `--attempted` | text | What you tried, in order. |
| `--expected` | text | What you expected to happen instead. |
| `--tool` | text | The tool or operation the report is about, e.g. query_dataset. |
| `--error-code` | text | The error code you got, if any, e.g. MCP_INVALID_ARGUMENTS. |
| `--severity` | `low`, `medium`, `high` | high: it blocked the task; medium: you worked around it; low: a papercut. |
| `--project` | text | The project's slug, from projects_list, when the report is about one project. |
| `--input-json` | JSON, `@file` or `-` | The whole input as one object; flags override its fields. |
