A dataset is a typed semantic model over a source table or view.

<CodeBlock>
```typescript
import { dataset, dimension, measure } from '@hypequery/datasets';

const Orders = dataset('orders', {
  source: 'orders',
  tenantKey: 'tenant_id',
  timeKey: 'created_at',
  dimensions: {
    id: dimension.number(),
    createdAt: dimension.timestamp({ column: 'created_at' }),
  },
  measures: {
    revenue: measure.sum('amount'),
  },
});
```
</CodeBlock>

`source` is the physical table or view name. The first `dataset()` argument is the logical dataset name. `tenantKey` and `timeKey` are physical column names used for runtime tenant isolation and time graining.

## Module pattern

Define datasets at the module level and export them from dedicated files.

<CodeBlock>
```typescript
// datasets/orders.ts
export const Orders = dataset('orders', {
  source: 'orders',
  tenantKey: 'tenant_id',
  timeKey: 'created_at',
  dimensions: {
    id: dimension.number(),
    status: dimension.string(),
    createdAt: dimension.timestamp({ column: 'created_at' }),
  },
  measures: {
    revenue: measure.sum('amount'),
  },
});
```
</CodeBlock>

## Public shape

A dataset can include:

- `source`
- `rowResolution` (explicit current rows for supported versioned tables)
- `tenantKey`
- `timeKey`
- `dimensions`
- `measures`
- `filters`
- `relationships`
- `limits`

See [Dimensions](/docs/datasets/dimensions), [Measures](/docs/datasets/measures), [Metrics](/docs/datasets/metrics), and [Relationships](/docs/datasets/relationships) for the main building blocks.

## Current rows from versioned tables

For a ReplacingMergeTree table, select its resolved rows explicitly:

<CodeBlock>
```typescript
const Users = dataset('users', {
  source: 'users',
  rowResolution: { kind: 'final', engine: 'replacing', deletedColumn: 'is_deleted' },
  dimensions: { id: dimension.number() },
  measures: { users: measure.count('id') },
});
```
</CodeBlock>

The table's own sorting key and version choose the current row. The optional
`deletedColumn` keeps only resolved rows whose deletion marker is zero. All
measures, tenant filters, relationships and time queries use that population.
Omit `rowResolution` to read physical rows as before.

For CollapsingMergeTree or VersionedCollapsingMergeTree, use
`{ kind: 'final', engine: 'collapsing', signColumn: 'sign' }` or
`engine: 'versioned-collapsing'`. Cancellation pairs resolve before positive
surviving rows are counted. Verify the engine family and column names against
the source metadata; replicated forms use the same policy.

This requires the ClickHouse query-builder execution path and a read-only user
that permits query settings (`readonly=2`). The planner disables PREWHERE for
these source reads to preserve version/deletion semantics. Other dialects and
semantic backends refuse resolved sources. SummingMergeTree and
AggregatingMergeTree need different measure semantics and are unsupported by
this policy. Portable deployment consumers must upgrade together to a protocol
version that understands `rowResolution`; stripping the field changes numbers.
