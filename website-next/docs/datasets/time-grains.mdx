---
title: Time grains
description: Aggregate metrics by minute, hour, day, week, month, quarter, and year.
---

import { CodeBlock } from 'fumadocs-ui/components/codeblock';

When a dataset has a `timeKey`, you can use `.by(grain)` on metrics to aggregate by time periods.

<CodeBlock>
```typescript
const revenue = Orders.metric('revenue', { measure: 'revenue' });
const monthlyRevenue = revenue.by('month');

await analytics.execute(monthlyRevenue, {
  dimensions: ['country'],
});
```
</CodeBlock>

Supported grains:

- `minute`
- `hour`
- `day`
- `week`
- `month`
- `quarter`
- `year`

`minute` and `hour` buckets keep their time of day, so a period reads like `2024-01-01 10:00:00`.

## Restricting grains

By default a dataset with a `timeKey` supports every grain. Pass `timeGrains` to narrow the list. Queries, pinned metrics (`.by()`), and the catalog's `supportedGrains` then use only those grains. This is how you refuse sub-day buckets when `timeKey` is a `Date` column with no time of day:

<CodeBlock>
```typescript
const DailySales = dataset('daily_sales', {
  source: 'daily_sales',
  timeKey: 'day',
  timeGrains: ['day', 'week', 'month', 'quarter', 'year'],
  dimensions: { day: dimension.timestamp() },
  measures: { revenue: measure.sum('amount') },
});
```
</CodeBlock>

## Publishing to Cloud

Sub-day grains work in local queries, Serve endpoints, and the local MCP server. Hypequery Cloud does not support them yet, because they need deployment contract 3 (RFC 0015), which publishing does not emit yet:

- publishing refuses a dataset whose `defaults.timeGrain`, or a metric pinned with `.by()`, uses `minute` or `hour`;
- published datasets advertise and accept only `day` through `year`.

## Time key and timestamp dimensions

`timeKey` names the physical timestamp column used for time bucketing. It does not create a selectable dimension by itself.

If you also want callers to select, filter, or group by that timestamp through the dataset API, add a timestamp dimension that maps a semantic name to the same column:

<CodeBlock>
```typescript
const Orders = dataset('orders', {
  source: 'orders',
  timeKey: 'created_at',
  dimensions: {
    createdAt: dimension.timestamp({ column: 'created_at' }),
    country: dimension.string(),
  },
  measures: {
    revenue: measure.sum('amount'),
  },
});
```
</CodeBlock>

With that setup, `.by('month')` buckets on `created_at`, while dataset queries can still use the semantic dimension name `createdAt`.
