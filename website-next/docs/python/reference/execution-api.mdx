---
title: hypequery.execution
description: Reference for the ClickHouse executors.
---

Importing `hypequery.execution` does not import the driver or open a connection. The driver is loaded when you create an executor.

| Install | Gives you |
| --- | --- |
| `pip install "hypequery[clickhouse]"` | The sync executor |
| `pip install "hypequery[clickhouse-async]"` | The async executor |

## Executors

| Export | Purpose |
| --- | --- |
| `create_clickhouse_executor(connection)` | A `ClickHouseExecutor`. Connects on demand |
| `create_async_clickhouse_executor(connection)` | An `AsyncClickHouseExecutor`. Connects on demand |
| `AsyncFromSyncClickHouseExecutor(client, control_client, *, max_concurrent=4)` | A bounded worker bridge for apps that already have a synchronous driver client |
| `ClickHouseConnection` | The connection protocol the executors accept |

Pass the executor to `create_dataset_client(executor=...)` or `create_async_dataset_client(executor=...)`.

## Results and read-only policy

`QueryRows` is the row type executors return.

`ReadonlyPolicy` is `"query"` or `"profile"`. In `query` mode, a user the driver reports as already read-only (`readonly` 1 or 2) doesn't get the planner's `readonly` setting, because a `readonly = 2` user would refuse it. Every other user gets all settings. `profile` mode does the same and also refuses a user that is not read-only.
