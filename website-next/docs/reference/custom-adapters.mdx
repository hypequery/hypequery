# Custom Adapters

`createQueryBuilder` accepts a custom `adapter`, letting the query builder run against any engine that speaks ClickHouse SQL — an embedded engine like [chDB](/docs/chdb), a proxy, or a test double:

<CodeBlock>

```typescript
import { createQueryBuilder, type DatabaseAdapter } from '@hypequery/clickhouse';

const db = createQueryBuilder<Schema>({ adapter: myAdapter });
```

</CodeBlock>

hypequery compiles queries to SQL with `?`-positional parameters client-side, so an adapter only has to run SQL text and return rows.

<Callout type="info" title="Contract stability">
  The <code>DatabaseAdapter</code> contract is stable to build against. Changes are additive
  (new optional methods); breaking changes will come with a migration path.
</Callout>

## The DatabaseAdapter Contract

<CodeBlock>

```typescript
interface DatabaseAdapter {
  readonly name: string;        // used in error messages and logs
  readonly namespace?: string;  // cache-key namespace; defaults to name

  query<T>(sql: string, params?: unknown[], options?: QueryExecutionOptions): Promise<T[]>;

  // Optional capabilities — builders throw a clear error when missing:
  stream?<T>(sql: string, params?: unknown[], options?: QueryExecutionOptions): Promise<ReadableStream<T[]>>;
  render?(sql: string, params?: unknown[]): string;
}
```

</CodeBlock>

### `query(sql, params, options)`

Receives SQL with `?` placeholders plus a parameter array. Render them with the exported `substituteParameters` so your output stays byte-identical to the built-in HTTP adapter — don't copy the logic:

<CodeBlock>

```typescript
import { substituteParameters } from '@hypequery/clickhouse';

async query(sql, params = []) {
  const finalSql = substituteParameters(sql, params);
  return runAndParseJsonEachRow(finalSql);
}
```

</CodeBlock>

Rows are expected in `JSONEachRow` semantics: one object per row, 64-bit integers as strings.

### `render(sql, params)` (optional)

Used by `toSQL()` for display. Implement it as `substituteParameters(sql, params)` for identical output.

### `stream(sql, params, options)` (optional)

Returns a `ReadableStream<T[]>` — one enqueued chunk per block of rows. Builders throw `Streaming is not supported by adapter "<name>".` when absent.

<Callout type="info" title="Inserts">
  A type-safe insert API is landing in <code>@hypequery/clickhouse</code>
  (<a href="https://github.com/hypequery/hypequery/pull/255">PR #255</a>). It adds an
  optional <code>insert</code> method to this contract — purely additive, existing adapters
  keep working unchanged — along with a <code>buildJsonEachRowInsert</code> helper so
  SQL-text engines can support inserts in a few lines. This page will document the full
  insert contract when it ships.
</Callout>

## Minimal Adapter Skeleton

<CodeBlock>

```typescript
import { substituteParameters, type DatabaseAdapter } from '@hypequery/clickhouse';

export function myAdapter(engine: MyEngine): DatabaseAdapter {
  const runText = (sql: string) => engine.run(sql, { format: 'JSONEachRow' });

  return {
    name: 'my-engine',

    async query(sql, params = []) {
      return parseJsonEachRow(await runText(substituteParameters(sql, params)));
    },

    render(sql, params = []) {
      return substituteParameters(sql, params);
    },
  };
}
```

</CodeBlock>

A real-world example is the chDB team's [`chdb/hypequery` adapter](https://github.com/chdb-io/chdb-node), which runs hypequery on embedded ClickHouse with exactly this shape — see [chDB (Embedded ClickHouse)](/docs/chdb).
